Chapter 1 — Python Basics

A program is a list of instructions a machine will follow exactly, and Python is one of the friendliest ways to write that list. This chapter shows you what Python actually is, how to get code into the interpreter, and the habits everything later depends on: assignment, input and output, indentation, and reading the error message when something breaks.

What Python is

Python is a programming language: a fixed set of rules for writing instructions, plus a defined meaning for every construct. The second thing called Python is the interpreter, the program installed on your machine that reads your code and carries out the instructions. The two are separate. The language is a document; the interpreter is software, and this course uses the standard one, CPython.

When you run a file, the interpreter does not act on your text character by character. It first compiles the file to an internal form called bytecode, then executes that. You never see the bytecode, but the two stages explain a behaviour that confuses beginners: a line can be perfectly valid Python and still fail, because syntax is checked before anything runs while names and values are only checked when the line executes.

Python is general purpose: short automation scripts, data analysis, web services, teaching. Its large standard library means common jobs need no extra installs. Install Python 3 and check it once: python --version should print a version starting with 3. If it prints 2.x, try python3 or, on Windows, py -3. Everything in this book targets Python 3.

The interpreter, the REPL, and scripts

You can hand Python code to the interpreter in two ways that matter now: interactively, and from a file.

Start python with no filename and you get the read-eval-print loop, universally called the REPL. It shows a prompt — >>> — reads one statement, evaluates it, prints the resulting value, and repeats. Values are echoed for you: typing 2 + 2 prints 4. Names you create stay alive until you exit, so the REPL is the right place to answer a small question: what does round(2.5) give, or what type does int("7") return? Exit with exit(), or Ctrl+D on macOS and Linux, Ctrl+Z then Enter on Windows. A block such as an if statement is entered across several lines, and the prompt changes to ... until you leave a blank line.

A script is a plain-text file whose name ends in .py. You run it with python hello.py, and the interpreter executes the file from top to bottom. There is no echo: the script produces output only where you print something. That difference catches almost everyone once. 2 + 2 typed at the prompt shows 4; the same line inside a file shows nothing at all. If a script appears to do nothing, it usually computed a value and dropped it.

# hello.py
name = input("What is your name? ")
print("Hello, " + name + "!")
# running: python hello.py
# What is your name? Ada
# Hello, Ada!

Variables and assignment

A variable is a name bound to a value. The single equals sign assigns: Python evaluates whatever is on the right, then binds the name on the left to that value. It does not assert that two things are equal — that is ==, and Chapter 3 uses it.

Rebinding is the everyday case. In score = score + 5 the right side is computed first using the old value of score, and only then is the name rebound to the result. Short forms exist: +=, -=, *=, //=. A name can point at an integer on one line and a string on the next, because the type belongs to the value, not to the name; Python is dynamically typed. You can check what a name currently refers to with type(score).

Names may contain letters, digits and underscores, must not start with a digit, are case-sensitive, and cannot be keywords such as if or for. Write them in lower_case_with_underscores. You never declare a variable, but you must assign before you use it: reading an unassigned name raises NameError.

score = 10
score = score + 5
print(score)          # 15

lives = 3
lives -= 1            # same as lives = lives - 1
print(lives)          # 2

x, y = 1, 2
x, y = y, x           # swap without a temporary name
print(x, y)           # 2 1

Printing output and reading input

print() writes its arguments to standard output, separating them with a single space and ending with a newline. Two keyword arguments change that: sep sets the separator, and end replaces the newline. print() also returns None; it is an action, not a value, so result = print("hi") stores nothing useful.

input() takes an optional prompt string, writes it, waits for the user to press Enter, and returns everything typed as a string. The trailing newline is stripped; nothing else is interpreted. That return type is the subject of a trap in the next chapter: text that looks like a number is still text.

name = input("Name: ")
print("Hello,", name)       # Hello, Ada

print("a", "b", sep="-")    # a-b
print("no newline", end="!")
print(" done")              # no newline! done

Indentation is syntax

In most languages, blocks are marked with braces. In Python, a block is marked by indentation, and the colon at the end of a header announces that a block follows. Lines with the same indentation belong to the same block; returning to a shallower level closes it. Indentation is not cosmetic here. Change it and you change what the program does, or you stop it from running at all.

Four spaces per level is the standard. The interpreter enforces consistency, not width, but four spaces is what readers expect. Never mix tabs and spaces in one block: the characters look identical on screen, and Python raises TabError because they are not the same. Set your editor to insert spaces when you press Tab. A block may not be empty; if you need a placeholder, write pass.

temperature = 31
if temperature > 30:
    print("It is hot.")
    print("Drink water.")
print("Done.")

Both indented lines run only when the condition is true, and the last line runs either way, because it sits back at the outer level.

Comments

A comment starts with # and runs to the end of the line. The interpreter ignores it entirely. Use comments to explain why a line exists, or to record a value the code cannot show by itself, such as the expected output. A comment that restates the code adds noise: score = score + 1 # add one to score tells a reader nothing.

Python has no block-comment syntax. For a longer note, write several # lines, or put a string on its own line as the first statement of a file or function. That is a docstring — documentation rather than a comment — and later chapters use it deliberately.

# Price after 8% sales tax.
price = 50
tax = price * 0.08        # 4.0
print(price + tax)        # 54.0

Reading a traceback

Two kinds of failure look different. A syntax error is caught before anything runs: you get the file, the line, a caret under the offending position, and a message such as SyntaxError: invalid syntax. An exception happens while running, and Python prints a traceback. Read it from the bottom up. The last line names the exception and says what went wrong. Above it are the frames, ordered with the most recent call last, so the frame just above the final line is where execution stopped, and the top frame is where the program started.

price = 20
count = 4
total = price * quanity    # typo: quanity
print(total)

# Traceback (most recent call last):
#   File "shop.py", line 3, in <module>
#     total = price * quanity
# NameError: name 'quanity' is not defined

The message gives you the name and the line number, and the fix is on that line. The exceptions you will meet first are NameError (an unassigned or misspelt name), TypeError (the wrong kind of value for an operation), ValueError (right type, unusable content, such as int("abc")), ZeroDivisionError, and IndentationError. Learn the names; the message is usually a complete diagnosis.

Tip. When a traceback points at a long expression, copy its pieces into the REPL one at a time and print their types. Checking takes seconds; guessing can take an evening.
Watch out. Windows hides file extensions, so saving a script as hello.py in Notepad can quietly produce hello.py.txt. python hello.py then fails, or runs an older file that happens to exist. Turn on file extensions in Explorer and keep scripts in their own folder.

Chapter 2 — Data Types and Operations

Every value in Python has a type, and every operator has rules about which types it accepts. Those rules turn a whole class of mysterious errors into obvious ones. Two habits are worth building: knowing when division stops being integer division, and never trusting a float to be exact.

The four core types

An int is a whole number: 10, -3, 0. Python integers have arbitrary precision, so they grow as needed instead of overflowing at some machine limit; 10 ** 100 is a perfectly ordinary value.

A float is a real number written with a decimal point or an exponent: 0.75, -2.5, 1e-3. Internally it is an IEEE 754 double: about 17 significant decimal digits, and no exact representation for most fractions.

A bool has exactly two values, True and False, and comparisons produce it. Booleans are a subclass of int, so True == 1 and True + True is 2; rely on that only with reason.

A str is text: a sequence of Unicode characters in quotes. Single and double quotes are equivalent; triple quotes make multi-line strings. None of these four types can be changed in place: they are immutable. A string method returns a new string, and only assignment keeps it. Lists and dictionaries, arriving in Chapter 4, are mutable — a difference that matters when two names refer to one object.

count = 10          # int
ratio = 0.75        # float
ready = True        # bool
label = "chunk"     # str

print(type(count))   # <class 'int'>
print(type(ratio))   # <class 'float'>

name = "ada"
name.upper()         # returns "ADA" and discards it
print(name)          # ada
name = name.upper()  # rebinding keeps the new string
print(name)          # ADA

Arithmetic and the division family

The familiar operators mean what you expect: +, -, *; with two ints the result is an int. Division is where beginners lose precision.

/ is true division and always returns a float, even when it divides evenly: 4 / 2 is 2.0, not 2. // is floor division: it divides and rounds down to the nearest whole number, so 7 // 3 is 2 and 7.0 // 3 is 2.0. Because it rounds toward negative infinity rather than toward zero, -7 // 2 is -4, not -3.

% gives the remainder, and it is defined to agree with //: a == (a // b) * b + a % b for any two ints. The sign of the result follows the divisor b, which surprises people: -7 % 2 is 1, while 7 % -2 is -1. ** raises to a power; an int base with a non-negative int exponent stays an int, and a negative exponent produces a float, so 2 ** -1 is 0.5. All three raise ZeroDivisionError on a zero divisor.

print(7 + 3, 7 * 3)   # 10 21
print(7 / 3)     # 2.3333333333333335
print(7 // 3)    # 2
print(7 % 3)     # 1
print(7 ** 3)    # 343

print(-7 // 2)   # -4
print(-7 % 2)    # 1
print(7 % -2)    # -1
print(4 / 2)     # 2.0  still a float
print(2 ** -1)   # 0.5

Precedence and associativity

Operations run in a fixed order: parentheses first, then **, then unary minus and plus, then *, /, // and %, then + and -. Comparisons and the logical operators come after that, and Chapter 3 covers them. Two consequences look wrong at first glance. Exponentiation binds tighter than unary minus, so -2 ** 2 is -4; write (-2) ** 2 when you mean positive four. And ** is right-associative, so 2 ** 3 ** 2 is 2 ** 9, which is 512, not 64.

The other operators of equal precedence group from the left: 20 // 3 // 2 is 6 // 2, which is 3. You need not memorise the table: parentheses cost nothing and reset every question. Add them when a reader would otherwise have to think.

print(2 + 3 * 4)     # 14
print((2 + 3) * 4)   # 20
print(-2 ** 2)       # -4
print((-2) ** 2)     # 4
print(2 ** 3 ** 2)   # 512
print(20 // 3 // 2)  # 3

Converting between types

Conversions build a new value; the original is untouched. int() on a float truncates toward zero: int(3.9) is 3, int(-3.9) is -3. On a string it parses a whole number and raises ValueError otherwise: int("3.7") fails, while int(" 42 ") succeeds because whitespace and a sign are allowed. float() parses decimal and exponent text, so float("1e3") is 1000.0; str() turns any value into readable text. bool() follows a rule Chapter 3 explores fully: zero, 0.0, the empty string and False become False, and everything else becomes True.

print(int("42"))        # 42
print(int(3.9))         # 3
print(int(-3.9))        # -3
print(float("2.5"))     # 2.5
print(float("1e3"))     # 1000.0
print(str(42) + "!")    # 42!
print(bool(""), bool("0"), bool(0))   # False True False

The string "0" counts as true because it is not empty, so conversion alone does not validate input. Check the text before converting when the user may type something else, as the last section shows.

Rounding and float imprecision

Because a float is stored in binary, most decimal fractions have no exact representation. 0.1 is slightly more than one tenth, 0.2 slightly more than two tenths, and their sum is not the stored value of 0.3. Printing hides most of it, because Python shows the shortest text that converts back to the same float; comparison exposes it.

round() with no second argument returns an int; with a second argument it rounds to that many decimal places, keeping the input's type. It rounds half to even, not half up: round(2.5) is 2 and round(3.5) is 4. Rounding cannot repair a value that was never exact, so round(2.675, 2) is 2.67, because the stored float sits just below the midpoint. Never test floats with ==. Compare with a tolerance, using math.isclose or an absolute difference, and keep money as integer cents or as decimal.Decimal when exactness is required.

print(0.1 + 0.2)            # 0.30000000000000004
print(0.1 + 0.2 == 0.3)     # False
print(round(0.1 + 0.2, 2))  # 0.3
print(round(2.5))           # 2
print(round(3.5))           # 4
print(round(2.675, 2))      # 2.67

Counting with range()

range() produces a run of integers, and its boundary rule is the source of the most common off-by-one bug in beginner code: it includes the start and excludes the stop. range(5) yields 0, 1, 2, 3, 4 — five numbers, not six, and never 5. range(1, 5) yields 1, 2, 3, 4. A third argument sets the step, so range(0, 10, 3) yields 0, 3, 6, 9, and a negative step counts down: range(5, 0, -1) yields 5, 4, 3, 2, 1. A step of zero raises ValueError.

Think of the stop value as the boundary where counting halts, not a member of the run. To count from 1 to n inclusive, write range(1, n + 1). To run exactly n times, write range(n). range is lazy: it computes each number as needed rather than storing the run. The list() wrapper below only prints the numbers; lists come in Chapter 4.

print(list(range(5)))            # [0, 1, 2, 3, 4]
print(list(range(1, 5)))         # [1, 2, 3, 4]
print(list(range(0, 10, 3)))     # [0, 3, 6, 9]
print(list(range(5, 0, -1)))     # [5, 4, 3, 2, 1]
print(len(range(5)))             # 5

The input() trap

input() always returns a string. It does not matter that the user typed digits; the result is text. Adding it to a number raises TypeError, comparing it to a number is simply unequal, and adding it to another string glues the two together. Convert with the type you need: int() for whole numbers, float() for decimals. Conversion can fail, so a program that asks for a number should expect a ValueError or check the text first.

print("5" + "3")             # 53
print(int("5") + int("3"))   # 8

age = int(input("Age: "))    # user types 30
print(age + 1)               # 31

height = float(input("Height in metres: "))
print(height * 100)          # 172.0

Stripping spaces converts cleanly: int(input("Age: ").strip()). An empty answer raises ValueError, which is why Chapter 3's conditions are the natural partner for input handling.

Tip. If a number must be exact — money, counters, scores — keep it as an int and scale it, for example cents instead of dollars, or grams instead of kilograms. Do the floating-point part only when you display the result.
Watch out. int() truncates toward zero, but // floors toward negative infinity, so they disagree below zero: int(-3.9) is -3 while -3.9 // 1 is -4.0. When negative values are possible, decide which behaviour you mean instead of mixing the two.

Chapter 3 — Control Structures

So far every program has run straight through, one line after another. Real programs make decisions, and Python makes them with conditions: comparisons that yield True or False, joined by the logical operators, and turned into branches by if. This chapter covers that machinery, including the shortcuts Python takes while evaluating it.

Relational operators

Six operators compare two values: == equal, != not equal, < less than, <= less than or equal, > greater than, and >= greater than or equal. Each produces a bool. Note the two equals signs: one assigns, two compare.

Equality compares values, not names or storage. Numbers compare across types, so 1 == 1.0 is True, and values of unrelated types are simply unequal rather than an error — "7" == 7 is False. Ordering is stricter: comparing a string with a number raises TypeError, because Python refuses to invent an order between them. Comparing two strings is alphabetical by character code, which is predictable for lowercase ASCII but not what you want when sorting text for humans.

Python also chains comparisons the way mathematics writes them. 0 < x < 10 means "x is greater than 0 and less than 10", and each value is evaluated once. It is not parsed as (0 < x) < 10.

Floats deserve one extra warning here. Because a float only approximates most decimals, testing two computed floats with == is unreliable. Keep == for ints, strings and bools, and compare floats with a tolerance, as Chapter 2 showed.

x = 7
print(x == 7)              # True
print(x != 7)              # False
print(x > 5)               # True
print(x <= 5)              # False
print(0 < x < 10)          # True
print("apple" < "banana")  # True
print("7" == 7)            # False

if, elif, else

An if statement evaluates a condition and runs its indented block only when the condition is true. A colon ends the header line, and the block is indentation, exactly as in Chapter 1. Optional elif branches are tested in order, and the first true one wins; the rest are skipped without being tested. Optional else runs when no condition was true and takes no condition of its own. Only one branch of a chain ever runs.

Because testing stops at the first match, order carries meaning. When the bands cover ranges, test the highest threshold first; if you test mark >= 50 before mark >= 90, a mark of 95 is labelled C and the program never looks further. An if without an else is fine: when the condition is false, nothing happens and execution continues after the block.

mark = 68
if mark >= 90:
    band = "A"
elif mark >= 70:
    band = "B"
elif mark >= 50:
    band = "C"
else:
    band = "F"
print(band)      # C

Logical operators and short-circuiting

and, or and not combine conditions. not inverts a truth value and always returns a bool. The other two return one of their operands, not necessarily a bool: and returns the first falsy operand, or the last operand if all are truthy; or returns the first truthy operand, or the last operand if all are falsy. That is why user or "guest" works as a default: if user is empty, the empty string is falsy and the second value comes back.

Both operators short-circuit. They evaluate the left operand, and stop when the result is already decided: and stops at a falsy left side, or stops at a truthy one. The right side is not evaluated at all. This is not a curiosity; it is how you write safe checks such as x != 0 and 10 / x > 2, which never divides by zero. Precedence runs not, then and, then or, so not a and b means (not a) and b. Add parentheses when a reader might hesitate.

x = 0
print(x != 0 and 10 / x > 2)   # False, no division happens
print(False and 1 / 0)         # False
print(True or 1 / 0)           # True
print(not True, not 0)         # False True
print("" or "guest")           # guest
print("Ada" and "Bob")         # Bob

Truthiness of empty values

An if accepts any value as its condition and converts it to a truth value. The falsy values are False, None, numeric zero in every form, the empty string, and later the empty list, tuple, dictionary and set. Everything else is truthy, including negative numbers, tiny fractions, and every non-empty string. Text is not parsed: "0", "False" and "no" are all truthy because each contains characters.

Whitespace counts as content too. The string " " is truthy even though it looks empty, which is why text read from a keyboard is normally stripped before the test: if answer.strip():. Empty means zero characters, not zero visible ones.

This gives you two idioms. Use if name: when empty text means "not provided". Use an explicit comparison when zero is a real value and must not be confused with missing: count of 0 is falsy, so if count: skips a legitimate zero. Later, when a value can be absent without being zero, you will test if value is not None instead.

print(bool(""), bool("0"), bool("False"))   # False True True
print(bool(0), bool(0.0), bool(-1))         # False False True

name = ""
if name:
    print("Hello,", name)
else:
    print("No name given")                  # No name given

Nested conditions

An if block may contain another if, indented one more level. Nesting is the direct way to express "only if the first thing is true, check the second". It is also easy to overdo: three levels deep, the reader has to hold three conditions in mind to know what a line does. When two conditions must both hold for the same action, combine them with and, saving a level. When a branch is empty in one case, look for a flat elif chain instead.

age = 20
has_ticket = True

if age >= 18:
    if has_ticket:
        print("Enter")
    else:
        print("Buy a ticket")
else:
    print("Too young")

# same decision, one level shallower
if age >= 18 and has_ticket:
    print("Enter")
elif age >= 18:
    print("Buy a ticket")
else:
    print("Too young")

The flattened version reads top to bottom without a detour. Keep nesting for genuinely different sub-questions, not for conditions that simply apply together.

A worked example

A leap year is a year divisible by 4, except years divisible by 100, unless they are also divisible by 400. That "except" and "unless" map directly onto an ordered elif chain, and the order is what makes it correct: the divisibility by 400 test has to come before the divisibility by 100 test, or the year 2000 would be rejected. Testing year % 4 == 0 first would wrongly accept 1900.

year = int(input("Year: "))
if year % 400 == 0:
    leap = True
elif year % 100 == 0:
    leap = False
elif year % 4 == 0:
    leap = True
else:
    leap = False

if leap:
    print(year, "is a leap year")
else:
    print(year, "is a common year")

Run it with 2024, 1900 and 2000. The program separates the decision from the reporting: one chain computes leap, and a second, simpler if prints. That split is worth copying. It keeps the tricky logic in one readable place and makes the output easy to change.

Input handling fits naturally here, with one sharp edge: int() raises ValueError when the text is not a whole number, and it raises before any condition is reached. That is a crash, not a wrong answer, so a program that reads numbers should check the text or expect the error. For a yes/no question, answer = input("Continue? ").strip().lower() or "no" makes the empty answer mean no, using or's short-circuit to supply a default. Then if answer == "yes" decides the branch, and any other text falls through to the same default behaviour.

Tip. When a condition misbehaves, print its parts instead of staring at the whole: print each comparison, then the combined expression. A branch that never runs is usually a condition that is always false for a reason you have not checked yet.
Watch out. if answer == "yes" or "y": is always true, because "y" is a non-empty string and therefore truthy — the or does not distribute over the comparison. Write if answer == "yes" or answer == "y": so each comparison is explicit.
