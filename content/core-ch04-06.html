Chapter 4 — Loops

So far every line of your programs has run exactly once, top to bottom. Most useful work repeats: add up a hundred readings, inspect every character in a sentence, print a pattern of stars. Writing the same line a hundred times is not programming — a loop is. This chapter covers the two loop forms, the ways to leave a loop early, and the counting habits that keep the boundaries right.

Repeating work with for and range()

For a fixed number of repetitions, for with range() is the clearest tool. The loop takes each value the iterable produces, binds it to a name, and runs the indented block once per value. When the values run out, the loop ends and execution continues below it.

for lap in range(5):
    print("lap", lap + 1)

range(5) produces 0, 1, 2, 3, 4 — five values, starting at zero and stopping before 5. That stopping rule is not a quirk to memorise: it is what makes range(n) mean “n items”, so the number of passes always equals the number in the brackets.

for n in range(1, 6):
    print(n * n, end=" ")
print()

With two arguments, range(1, 6) starts at 1 and produces 1 through 5 — five values again, because 6 − 1 = 5. A third argument is the step, and it may be negative:

for n in range(10, 0, -2):
    print(n, end=" ")
print()          # 10 8 6 4 2

The loop variable is an ordinary variable and survives after the loop, holding its last value. Do not rely on that; treat it as belonging to the loop. If you only need to repeat something and never use the number, name the variable _ to say so.

Looping over sequences

for works on anything that can hand out items in order. A string hands out its characters one at a time, so counting becomes a loop plus a condition:

word = "banana"
vowels = 0
for ch in word:
    if ch in "aeiou":
        vowels += 1
print(vowels)          # 3

vowels += 1 is shorthand for vowels = vowels + 1. The variable is created before the loop and updated inside it — a pattern used constantly, and one that only works because the name survives between passes.

Sometimes you need the position as well as the value. Then loop over indexes that the string actually has:

word = "loop"
for i in range(len(word)):
    print(i, word[i])

len(word) is 4, so range(4) gives 0 through 3, exactly the valid indexes. That is the safe pattern. range(len(word) + 1) would ask for index 4 and raise IndexError on the last pass.

Watch out. range never includes its stop value. range(5) is 0–4, range(1, 5) is 1–4, and a loop meant to reach 5 needs range(1, 6). If a loop runs one pass too few or too many, check the boundary first: range(start, stop) always produces exactly stop - start values, so count them on your fingers before hunting for a deeper bug.

while loops: repeat until something changes

while rechecks a condition before every pass and stops the moment it is false. Use it when the number of repetitions depends on the data rather than a count you already know.

n = 100
steps = 0
while n > 1:
    n = n // 2
    steps += 1
print(steps)          # 6

// is integer division: 25 // 2 is 12, not 12.5. The condition is tested again after each pass, and the body moves n toward 1, so the loop is guaranteed to end. Delete the line that changes n and the loop never stops — the classic infinite loop. When a while runs forever, the cause is almost always a body that never moves the condition toward false.

The loop must make progress, and it must make it in the right direction. while n > 1 with n = n + 1 also runs forever, and it looks correct at a glance.

break, continue, and the loop else

break leaves the loop immediately; the rest of the block is skipped and execution continues after the loop. continue skips the rest of the current pass and starts the next one.

for n in range(10, 30):
    if n % 7 == 0:
        print("found", n)
        break
    print("checked", n)
else:
    print("no multiple of 7")

The else clause on a loop runs only when the loop finished without hitting break. Read it as “no break happened”, not “the loop ran”. That makes it the natural companion of a search: either you found something and broke out, or the search exhausted its candidates and the else reports the miss. continue does not affect it — finishing the last pass normally still runs the else.

total = 0
for n in range(1, 11):
    if n % 2:
        continue
    total += n
print(total)          # 30

n % 2 is 1 for odd numbers and 0 for even, so the condition is true exactly when n is odd. Those passes are skipped before the addition. while loops accept an else too, and while True: with a break inside is an idiomatic way to say “loop until found”.

Nested loops: tables and triangles

Put one loop inside another and the inner loop runs to completion for every single pass of the outer one. The outer loop controls rows; the inner loop controls what goes in each row:

for a in range(1, 4):
    for b in range(1, 4):
        print(f"{a * b:3}", end="")
    print()

f"{a * b:3}" right-aligns the number in three characters, which lines the columns up. The inner loop prints three products, then the bare print() ends the row. Three rows of three means nine prints in total, so the work multiplies rather than adds.

Star patterns work the same way, with the inner count driven by the outer variable. That dependency is what turns a rectangle into a shape:

for row in range(1, 6):
    for star in range(row):
        print("*", end="")
    print()

Row 1 prints one star, row 2 prints two, and so on to five. Swap range(row) for range(6 - row) and the triangle turns upside down. Building each row in a string first is often cleaner than printing piece by piece: start with line = "", append characters in the inner loop, then print the finished line.

Counting, accumulating, and designing in steps

Two patterns cover most loop work. A counter starts at 0 and adds 1 per event. An accumulator starts at 0 (or at "" for text) and adds each value that qualifies. Both are created before the loop and read after it:

total = 0
count = 0
for n in range(1, 101):
    if n % 3 == 0 and n % 5 != 0:
        total += n
        count += 1
print(total, count)                 # 1368 27
print(round(total / count, 2))      # 50.67

Before writing that code, write the algorithm in words: look at every number from 1 to 100; keep the ones divisible by 3 but not by 5; add each to a running total; count them; divide at the end. Each clause maps to one line. This step is the actual design work, and doing it in prose first is faster than debugging a loop whose purpose you never stated.

Then check the edges while the plan is still in your head. What if no number qualified? count would be 0 and the division would raise ZeroDivisionError, so a guard is the honest fix. Tracing one pass by hand — n = 3 qualifies, n = 15 does not — catches most boundary mistakes before they become bugs.

Tip. While building a loop, print the loop variable and the accumulator on the first two or three passes, then delete the print. Seeing n=1 total=0 followed by n=2 total=3 tells you in five seconds whether the boundary and the order of operations are right.

Chapter 5 — Composite Types

One value is rarely enough. A list keeps many values in order, a tuple keeps a small fixed group, a dictionary maps names to values, and a set answers “is this value already known?”. These four types carry most real programs, and the majority of bugs in them come from one question: did you copy the data, or just the name pointing at it?

Lists: index, slice, change

scores = [72, 88, 95, 60]
print(scores[0], scores[-1])        # 72 60
print(scores[1:3])                  # [88, 95]
scores[1] = 90
scores.append(100)
print(scores)                       # [72, 90, 95, 60, 100]
print(len(scores))                  # 5

Square brackets build a list. Indexes start at 0, and negative indexes count from the end, so -1 is the last item. A slice a[start:stop] returns a new list of the items from start up to but not including stop — the same stopping rule as range.

Lists are mutable: scores[1] = 90 replaces an item in place and the list keeps its identity. Slices can be assigned to as well, and the replacement need not have the same length, so a slice assignment can grow or shrink the list:

letters = ["a", "b", "c", "d"]
letters[1:3] = ["B", "C", "D"]
print(letters)          # ['a', 'B', 'C', 'D', 'd']
letters[1:4] = []
print(letters)          # ['a', 'd']

An empty slice assignment deletes the section. This is powerful and easy to misuse; when you only need to replace one item, index it directly.

Adding, removing, sorting — and one trap

names = ["zoe", "adam", "mia"]
names.sort()
print(names)                        # ['adam', 'mia', 'zoe']
print(sorted(names, reverse=True))  # ['zoe', 'mia', 'adam']
names.append("li")
names.remove("mia")
print(names.pop())                  # li
print(names)                        # ['adam', 'zoe']

sort() sorts in place and returns None, so names = names.sort() leaves you with None. sorted() builds a new list and leaves the original alone — use it when the original order still matters. append adds to the end, insert(i, x) puts x at index i, remove(x) deletes the first item equal to x, and pop() removes and returns the last item.

Watch out. Never remove items from a list while looping over that same list. The loop keeps an internal position, and deleting an item shifts everything after it one place left, so the item that slides into the current position is never inspected.
nums = [1, 2, 2, 3, 2]
for n in nums:
    if n == 2:
        nums.remove(n)
print(nums)          # [1, 3, 2] — one 2 survived

The result is not “all 2s removed” but “some 2s removed”, which is worse because it looks nearly right. The clean fix is to build a new list: nums = [n for n in nums if n != 2]. If you truly must remove in place, loop over a copy — for n in nums[:] — and accept that you are doing two things at once.

Names point at values: aliasing and copying

The most important idea in this chapter: a variable does not contain a list. It contains a reference — a pointer to the list object, which lives elsewhere. Assignment copies the reference, so two names can point at the same object. The data is shared, and a change made through one name is visible through the other.

a = [1, 2, 3]
b = a
b.append(4)
print(a)          # [1, 2, 3, 4] — a changed too
print(a is b)     # True — one object, two names

is asks “same object?”; == asks “same contents?”. After b = a both answers are true. To get an independent list, copy it:

a = [1, 2, 3]
c = a[:]
c.append(4)
print(a)          # [1, 2, 3] — untouched
print(a is c)     # False
print(a == c)     # False

a[:], list(a), and a.copy() all make a shallow copy: a new outer list whose items are the same objects as before. That is enough for numbers and strings, which cannot change. It is not enough for a list of lists:

grid = [[0, 0], [0, 0]]
other = grid[:]
other[0][0] = 9
print(grid)       # [[9, 0], [0, 0]] — the inner row is shared

The outer list was copied; the two inner lists were not. Writing into row 0 through the copy writes into the row both grids point at. For nested data, copy the whole structure:

import copy
grid = [[0, 0], [0, 0]]
safe = copy.deepcopy(grid)
safe[0][0] = 9
print(grid)       # [[0, 0], [0, 0]]
Watch out. b = a makes no copy at all. If a change made “in the copy” appears in the original, two names point at one object — check with a is b. And if a change to one element of a copied list shows up in the original, the copy was shallow and the element was itself a list or dictionary.

List comprehensions

Most loops that build a list follow one shape: start empty, loop, append. A list comprehension writes that shape as a single expression:

squares = [n * n for n in range(6)]
print(squares)                          # [0, 1, 4, 9, 16, 25]

evens = [n for n in range(20) if n % 2 == 0]
print(evens)                            # [0, 2, 4, ..., 18]

words = ["Loop", "list", "map", "while"]
short = [w.lower() for w in words if len(w) <= 4]
print(short)                            # ['loop', 'list', 'map']

Read it in execution order even though the result is written first: the for names the source, the if filters what passes, and the expression at the front says what each surviving item becomes. Keep comprehensions to one for and at most one if. If it needs two loops or an explanatory comment, a plain loop is easier to read, and readable beats short.

Tuples: fixed groups you can trust

point = (3, 5)
x, y = point            # unpacking
print(x, y)             # 3 5
print(point[0])         # 3

single = (42,)          # the comma makes the tuple
print(type(single))     # <class 'tuple'>

Tuples are like lists that cannot change: no append, no item assignment. That restriction is the point. A tuple promises its values stay put, so you can pass it around without wondering who will modify it. Unpacking turns a group into named parts in one line, and a swap is just unpacking: x, y = y, x.

Because they cannot change, tuples can be dictionary keys:

screens = {(1920, 1080): "landscape", (1080, 1920): "portrait"}
print(screens[(1920, 1080)])      # landscape

Dictionary keys must be immutable, because the dictionary finds them through a hash that must never change. A tuple of numbers hashes to the same value forever; a list’s contents can change, so a list cannot be a key. A tuple is hashable only if everything inside it is — (1, [2]) is not.

Choose a tuple when the group is fixed and position carries meaning — a coordinate, a date, a row read from a file — and a list when you will add, remove, or sort. The type documents the intent, and a reader can trust a tuple not to change underneath them while they work.

Dictionaries, nested data, and sets

prices = {"apple": 1.2, "pear": 0.8}
print(prices["apple"])              # 1.2
prices["plum"] = 1.5                # add
print(prices.get("kiwi", 0))        # 0 instead of KeyError
print("pear" in prices)             # True — checks keys
for name, price in prices.items():
    print(name, price)

prices[key] raises KeyError when the key is missing, while .get(key, default) returns the default instead — usually what you want for an optional lookup. Iterating a dictionary yields keys; .keys(), .values(), and .items() make the intent explicit. Dictionaries keep insertion order, but they are not sorted: sort the keys when order matters.

Two habits prevent most dictionary bugs: use .get for keys that may be absent, and decide once what a missing key means — zero, None, or an error. Mixing those answers inside one function is how a KeyError escapes into production.

Values can be anything, including other dictionaries. Each lookup then applies one level at a time:

people = {
    "ada": {"role": "engineer", "years": 3},
    "grace": {"role": "admiral", "years": 9},
}
print(people["ada"]["role"])        # engineer
people["ada"]["years"] += 1
print(people["ada"]["years"])       # 4

A set stores unique values and answers membership very fast. It drops duplicates and keeps no order:

seen = set()
for word in "the cat the dog the".split():
    seen.add(word)
print(seen)              # {'the', 'cat', 'dog'} — order varies
print(sorted(seen))      # ['cat', 'dog', 'the']

Use a set for “is this already known?” and for deduplication, not for ordering. If both matter, sort the set or use a dictionary to keep insertion order.

Tip. A dictionary is the natural counter. counts[word] = counts.get(word, 0) + 1 adds one to the tally and starts a new one at 1 automatically, with no if word in counts branch.

Chapter 6 — Functions and Code Reuse

Your scripts are getting long, and the same three lines keep appearing in different places. A function gives that work a name so you can call it by name. That is not just tidiness: a function is a testable unit, a boundary for names, and the only practical way to build something larger than a page.

Defining and calling functions

def area(width, height):
    """Return the area of a rectangle."""
    return width * height

print(area(3, 4))       # 12

def introduces a name, a parameter list, and an indented body. Nothing runs when the definition is read; the body runs when it is called. The names in the definition are parameters; the values passed in are arguments. area(3, 4) binds width=3 and height=4 for that call only, which is why one function can serve a thousand different calls.

The string just under def is a docstring. It states the contract — what goes in, what comes out — and tools show it: help(area) prints it, area.__doc__ returns it. Write it for a caller who has not read the body.

Arguments arrive as references, exactly like assignment. A function that mutates a list parameter changes the caller’s list, while one that rebinds the parameter changes nothing outside the call. The rule from Chapter 5 — assignment copies the name, not the data — applies to every call you make.

return: sending a value back

def shout(text):
    return text.upper() + "!"

def report(text):
    print(shout(text))

value = report("hello")     # prints HELLO!
print(value)                # None

return ends the function and hands a value to the caller. A function that only prints returns None, and None is not a string you can keep working with. That is why report is hard to reuse and shout is easy: one computes, the other only displays.

return may appear anywhere in the body, and the first one reached wins:

def sign(n):
    if n > 0:
        return "positive"
    if n < 0:
        return "negative"
    return "zero"

A function with no return at all also gives back None. And a function can return several values at once by returning a tuple, which the caller unpacks: return low, high followed by low, high = ....

Default and keyword arguments

def greet(name, greeting="Hello", punctuation="!"):
    return f"{greeting}, {name}{punctuation}"

print(greet("Ada"))                     # Hello, Ada!
print(greet("Ada", "Hi"))               # Hi, Ada!
print(greet("Ada", punctuation="?"))    # Hello, Ada?
print(greet(greeting="Hey", name="Bo")) # Hey, Bo!

Defaults make a parameter optional, so the common case stays short and the unusual case stays possible. Arguments passed by name are keyword arguments: they may appear in any order, but each must follow the positional arguments in the call. A parameter without a default cannot follow one with a default, and an argument may not be filled twice — greet("Ada", name="Bo") raises TypeError.

Keyword arguments pay for their extra typing at the call site. open("notes.txt", encoding="utf-8") says what it means; a chain of anonymous positional arguments does not.

The mutable default trap

def add_item(item, basket=[]):        # looks harmless, is not
    basket.append(item)
    return basket

print(add_item("apple"))              # ['apple']
print(add_item("pear"))               # ['apple', 'pear']
print(add_item("plum"))               # ['apple', 'pear', 'plum']

Each call that omits basket is supposed to start with an empty list, yet the calls pile up. The reason is timing: the default expression [] is evaluated once, when the def statement runs, and the resulting list is stored on the function object. Every later call that omits the argument receives that same stored list. The function is quietly accumulating every caller’s data in one shared object — a real defect that ships in real code, not a puzzle.

def add_item(item, basket=None):
    if basket is None:
        basket = []
    basket.append(item)
    return basket

None becomes the sentinel, and a fresh list is built inside each call. Test with is None, never with if not basket: an empty list passed deliberately is falsy, and that test would silently throw the caller’s list away. The same trap applies to {} and set() defaults, so the rule is: never put a mutable object in a default.

Scope and LEGB

Names live in scopes, and Python looks a name up in a fixed order: Local, Enclosing, Global, Built-in — LEGB.

count = 0                   # global

def bump():
    count = 1               # local; a different name
    return count

print(bump(), count)        # 1 0

Inside bump, count = 1 creates a local variable; the global is untouched. Assignment always binds a name in the current scope. To change the module-level name you must declare it:

def reset():
    global count
    count = 0

global works and is worth knowing. It is also worth avoiding. A function that reads and writes module-level state is hard to test, because calling it twice is not the same as calling it once. Pass values in as parameters and return results instead; keep global for small scripts and counters you genuinely mean to share.

Enclosing covers nested functions. A function defined inside another one can read the outer function’s names, and it remembers them after the outer call has finished:

def make_adder(n):
    def add(x):
        return x + n        # n comes from the enclosing scope
    return add

add5 = make_adder(5)
print(add5(3))              # 8

That is a closure, and it is the reason nested functions are useful: the inner function carries its context with it.

Small functions, docstrings, and recursion

A good function does one thing you can describe without “and”. It takes its inputs as parameters, returns its result, and touches nothing else. That makes it testable in isolation, and a function you can test is a function you can change without fear. Twenty small functions stay understandable for years; one two-hundred-line function is understood once and then avoided.

A practical test of the rule: describe the function in one sentence without using the word “and”. If the sentence needs an “and”, two functions are hiding inside one. Splitting them costs a name and saves an afternoon.

Document the ones you will call again, even if “again” means later today. One line, imperative, starting with a capital: “Return the area of a rectangle.” Add a note when behaviour is surprising — units, empty input, errors raised. The docstring is also the first thing help() shows, so it is the cheapest documentation you will ever write.

Write down the surprising part explicitly: that the function sorts its argument in place, that it raises ValueError on empty input, that a result is rounded. A caller who reads only the docstring should not be able to misuse the function.

Recursion is not a trick for its own sake. It is the natural fit when a structure contains smaller copies of itself, which is why trees and nested dictionaries take to it and plain counting does not.

Recursion is a function calling itself on a smaller version of the same problem. Factorial is the standard first example, because 5! = 5 × 4 × 3 × 2 × 1 and n! = n × (n-1)! are the same statement:

def factorial(n):
    """Return n! for n >= 0."""
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(5))     # 120

Two parts are mandatory. The base case returns without recursing, and the recursive case moves toward the base case. Remove the base case and the calls never stop; fail to shrink the argument and they never reach it.

Watch out. Every pending call sits on the call stack, and Python caps that stack. sys.getrecursionlimit() is usually 1000, so factorial(2000) raises RecursionError even though the arithmetic is fine. Python does not optimise tail calls, and a recursion thousands of levels deep fails where a loop would succeed. Use recursion where the data is naturally nested — trees, nested dictionaries — and a loop for plain counting.
Tip. When a function needs more than about twenty lines, or a comment explaining a middle step, that step wants to be its own function with its own name. The name is the documentation.
